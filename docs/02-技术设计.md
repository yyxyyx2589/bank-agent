## 1. 架构总览

```
                         ┌─────────────────────────────────────────┐
START ──► [guard 合规守卫]──┤ REFUSE  ───────────────►[synthesis]──►END
                         │ ESCALATE────────────────►[ticket]──────►END
                         │ PASS ───►[supervisor]◄──────┐
                         └────────────────────────────┤
                                                      │
                          ┌───────────────────────────┴───────────┐
                          ▼                   ▼                   ▼
                    [knowledge]          [rules]            (ticket 兜底)
                    RAG+置信度           查费率/规则表         低置信转人工
                          │                   │
                          └────────►[supervisor]（回环，带新证据再决策）
                                      │
                                 证据足够
                                      ▼
                                 [synthesis]──►END
                                 组装带引用答案
```

**六个节点**，每个节点的职责边界、工具权限、成功标准：

| 节点 | 类型 | 工具权限 | 成功标准 | 失败兜底 |
|---|---|---|---|---|
| Guard | 纯规则引擎 | 无 | 护栏/资金安全/投诉/要求人工 100% 命中 | 命中即确定，无兜底需求 |
| Supervisor | 确定性路由 | 无 | 路由可归因（不靠 LLM 心情） | iterations≥3 强制收敛 |
| Knowledge | RAG 检索 | search_knowledge | sim/kw_coverage 准确 | 低置信由 supervisor 转 rules/ticket |
| Rules | 结构化查询 | get_product_rate, check_business_rule | 精确值正确 | 工具无结果由 synthesis 转人工 |
| Ticket | 副作用写操作 | create_ticket, escalate_to_human | 转接单号生成 | 确定性路径不依赖 LLM |
| Synthesis | 答案合成 | 无 | 答案带引用、不编造 | 证据不足明确拒答 |

## 2. 状态契约（AgentState）

所有节点读写同一个 `TypedDict`（`src/state.py`）。字段最小化原则：大块数据（chroma 向量、sqlite 记录）留外部存储，state 只放决策信号和引用。

```python
class AgentState(TypedDict, total=False):
    query: str                       # 输入
    messages: list[dict]             # 对话历史
    gate: str                        # PASS/REFUSE/ESCALATE
    gate_reason: str                 # 命中规则说明（可溯源）
    rag_evidence: dict | None        # {best_sim, best_kw_coverage, results}
    confidence_level: str            # high/mid/low
    rule_evidence: list[dict]        # 费率/规则查询结果
    ticket: dict | None              # 工单/转接记录
    ticket_intent: dict | None       # Guard→Ticket 确定性意图
    next_agent: str                  # supervisor 决策
    iterations: int                  # 调度轮数
    answer: str                      # 最终答案
    citations: list[str]             # 引用 kb-xxx/R-xxx/工单号
    trace: list[dict]                # 每步记录，评测归因
```

**踩坑记录**：`ticket_intent` 最初没声明在 schema 里，guard 返回后被 LangGraph 丢弃，ticket 收到 None 误走 LLM 分支。**TypedDict 未声明的字段不会被图保留**——这是 v2 开发中第一个实质性 bug。

## 3. Supervisor 路由规则（确定性，可归因）

区别于开源项目普遍用 LLM 做 supervisor 路由，本项目路由层完全用规则：

```python
gate == REFUSE            → synthesis
gate == ESCALATE          → ticket
gate == PASS:
  无 rag_evidence           → knowledge（先拿置信度）
  level == high 且无数字信号  → synthesis（直答）
  level == high 且有数字信号  → rules（补查表）
  level == mid               → rules（若已查过→synthesis）
  level == low               → rules（若已查过→ticket 兜底）
  iterations ≥ 3            → synthesis（强制收敛，防死循环）
```

**数字/条件信号**（正则 + 关键词）：`\d+[%万千百元]`、`分\d+期`、`利率/费率/手续费/起存/限额`、`能不能/要不要/是否/能不能代办`。

**为什么不用 LLM 路由**：v1 实测资金安全场景提示词服从率约 50%；路由不一致则评测无法归因（分不清是检索错、判断错还是路由错）。确定性规则让每次失败都能定位到具体节点。

## 4. 置信度阈值（v1 标定沿用）

| 阈值 | 值 | 含义 | 标定依据 |
|---|---|---|---|
| SIM_HIGH | 0.55 | ≥ 高置信直答 | 正样本均值 0.699 与负样本上限 0.434 之间，留 0.116 余量 |
| SIM_LOW | 0.40 | < 低置信拒答 | 正样本最低 0.445 留 0.045 余量，避免标准问题被拒 |
| KW_COVERAGE_LOW | 0.15 | 关键词覆盖率门槛 | 卡在正样本最低 0.167 与负样本最高 0.143 之间 |

综合评分 = `0.7*sim + 0.3*kw_coverage`。重标后 24 正样本 22 直答/2 走 Agent/0 拒答；7 负样本 0 误判直答。

## 5. 工具权限矩阵（最小权限）

| 工具 | Knowledge | Rules | Ticket | 说明 |
|---|---|---|---|---|
| search_knowledge | ✓ | | | 检索是 Knowledge 专属 |
| get_product_rate | | ✓ | | 精确数字必须查表 |
| check_business_rule | | ✓ | | 条件判定查规则表 |
| create_ticket | | | ✓ | 副作用写操作隔离 |
| escalate_to_human | | | ✓ | 转接是即时动作 |

**设计意图**：Rules Agent 拿不到 rag_search，避免它和 Knowledge 重复检索；Ticket 是唯一写操作节点，爆炸半径最小。Guard 不持有任何工具——它是规则引擎不是工具调用者。

## 6. 评测设计（eval-driven）

评测集（`data/eval_questions.jsonl`，21 题）覆盖五类：
1. 标准业务问题（高置信直答）
2. 具体数字查询（必须查表）
3. 条件判定（必须查规则表）
4. 行外护栏（必须拒答）
5. 资金安全/投诉（必须转人工）

每题断言四件事：
- `gate` 正确（PASS/REFUSE/ESCALATE）
- 链路正确（是否经过 rules/ticket）
- 答案带引用（citations 非空 或 明确拒答）
- 关键事实正确（数字类答案含精确值）

trace 字段让失败可归因到具体节点。
